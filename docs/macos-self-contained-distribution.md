# EDMORE macOS 自包含分发方案（归档）

归档日期：2026-09-15

状态：待实施。本文件记录后续方案，不表示相关功能已经完成。

## 目标

用户下载 DMG，拖入 Applications，打开 App，配置自己的 API Key 后即可使用客户端，无需安装 Node、克隆源码或运行 npm 命令。

## 当前情况

- Mac App 是 EDMORE client 的桌面控制界面，需要外部 Node 和已安装依赖的 client 目录。
- 现有 DMG 不包含上述运行环境，因此还不是独立可用的安装包。
- 当前开发构建使用 ad-hoc 签名，未完成 Apple 公证。
- API Key 当前保存在用户目录的 `~/.dsh/edmore/.credentials.yaml`，是权限为 `600` 的本地明文文件，不是 macOS 钥匙串存储。

## 后续实施步骤

1. 自包含打包
   - 将现有 EDMORE client、生产依赖和适配 CPU 架构的 Node 运行环境一起放入 `.app`。
   - 修改启动器，默认启动内置 client，不再要求用户选择源码目录。
   - 验证原生依赖、动态加载模块和 Electron 打包路径；需要时将运行文件放在 ASAR 外。
   - 保留 EDMORE server/client 的现有架构，不再引入独立 Harness 产品目录。

2. 首次启动配置
   - 引导用户设置模型提供方、API Key、模型和 MCP 服务地址。
   - 将密钥存入 macOS 钥匙串，并设计现有凭据的迁移流程。
   - 会话、配置和日志放在用户可写的应用数据目录，不写入 `.app`。
   - 迁移现有 `~/.dsh/edmore` 数据时保留备份，避免丢失会话或覆盖用户配置。

3. 区分客户端与仪器部署
   - 自包含 App 提供客户端启动、模型配置和对话能力；模型访问仍需要有效凭据和网络。
   - SEM 控制仍依赖仪器端的 `ptycho-sem` 及相关 MCP 服务。
   - NionSwift 插件仍部署在 NionSwift 所在环境，不应让用户误以为 DMG 自带完整仪器环境。
   - MCP 未连接时明确显示状态，不执行硬件操作；保持原有审批与安全检查。

4. 分发准备
   - 正式分发前核实 Apple 当前要求，使用 Developer ID 签名，完成公证并装订公证票据。
   - 优先提供 Apple Silicon 安装包；根据需求增加 Intel 版或评估 Universal 构建。
   - 检查随包依赖的许可证和再分发要求，保留必要声明。
   - DMG 放在 GitHub Releases，源码和打包脚本放在 Git 仓库；不将安装包提交到 Git 历史。
   - 测试版标记 Pre-release；公开仓库的 Pre-release 仍公开可见，不等于内部访问控制。
   - 自动更新可以后续增加，不作为首个自包含版本的前置条件。

## 验收条件

- 在没有开发环境、没有 Node、没有源码目录的干净 Mac 用户环境中完成安装和启动。
- 首次配置 API Key 后可进行实际模型对话；密钥不出现在日志、安装包或源码中。
- 退出、重启、关闭窗口留后台等生命周期行为正常，不产生重复 client 进程。
- 升级应用不覆盖用户凭据、会话和设置。
- 仪器未连接时客户端仍能打开并清晰报告状态；硬件测试需另行在受控环境进行。
- 从实际下载的 DMG 验证签名、公证、CPU 架构和依赖加载，而不只测试本机开发构建。

## 实施范围

未来主要修改 `desktop/` 的打包、启动和首次配置流程，以及 client 的凭据存储适配。当前仅归档方案，不实施、不创建发布或推送。
